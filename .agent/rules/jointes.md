---
description: Invariants de sûreté pour la commande Devin `/jointes <agent>`.
trigger: always_on
---

- Pour `/jointes <agent>`, appliquer la skill `jointes` (workspace `.devin/skills/` ou globale `%APPDATA%\devin\skills\jointes`); la référence canonique est `docs/protocole-binome/README.md` (ou la copie injectée `.agent/docs/protocole-binome/README.md`).
- `/jointes` est une skill Devin; ne pas prétendre qu’elle apparaît dans le menu d’un ACP tiers. Le menu ACP dépend des commandes annoncées par le provider sélectionné.
- `/chat-id` est en lecture seule : retourner l’ID exact de la session ACP focalisée ou de la session Devin courante; en cas d’ambiguïté, demander un ID explicite et ne jamais choisir la plus récente.
- N’annoncer un join réussi qu’après requête/ACK frais corrélés par `pairId`, `session`, transports, providers et IDs exacts; exiger `established: true`. Les handshakes legacy sont ignorés et le `hint` seul ne prouve rien.
- Séparer strictement les modes `hub`, `acp` et `cli`; Kilo/Hermes peuvent avoir un ID ACP et un ID CLI différents. Aucun fallback d’un mode/session vers l’autre.
- Pour `--peer-via hub` (AGY = Tango), JAMAIS choisir un modèle à la place de Tango : passer uniquement le label du modèle **actuellement sélectionné dans sa cascade** (défaut lisible via `agy-hub.js models` → `defaultOverrideModelConfig`, ou le nom affiché dans l’UI Antigravity ; en douter → demander à l’utilisateur). Un `--model` inventé change le modèle de Tango = faute grave. Pour ACP/CLI, omettre `--model`.
- Pour ACP, ne router que vers un couple exact `providerId/sessionId` présent dans l’état ACP, activé et rattaché au workspace courant; restaurer l’onglet existant et revérifier le focus. Session absente, désactivée ou non focalisable = `skipped`.
- Depuis `orchestrator-monitor` 0.0.58, le send ACP vers les providers tiers passe par `agent-bridge/acp-inject.js` : client ACP stdio vers le processus du provider (`initialize` → `session/load`/`session/resume` → `session/prompt`) sur l’ID exact. Providers non mappés ou indisponibles = `skipped`; ne jamais utiliser une commande générique Devin dont le payload ne cible pas la session.
- `acp-inject.js --provider <id> --session <id> --prompt "<t>" --wait turn` est la voie de vérification ping-pong : indépendante du focus IDE, elle renvoie `delivered` + `reply`. `delivered`/`pending` seul ≠ réponse; exiger `stopReason: end_turn` + texte `reply`.
- `binome.js send/join` valide l’identité locale via l’onglet focalisé : si l’utilisateur regarde l’onglet du pair, la validation échoue — refocaliser le chat Devin ou utiliser `acp-inject.js`, ne pas boucler. Ne jamais passer `--to` avec `send` (annule la recherche du pair).
- Une requête entrante non acquittée (< 15 min) bloque les joins du même provider : lire `.agent/comms.jsonl` et acquitter/attendre l’expiration avant de réessayer.
- En cas d’IDs locaux contradictoires (`current-cascade` bare vs `--raw`), demander une fois à l’utilisateur et prendre l’ID confirmé; ne jamais alterner.
- Un pair ACP peut écrire dans le workspace : lui interdire de modifier `.agent/agent-bridge/*` dans le prompt de join; après join, `node --check` les fichiers bridge et traiter toute modification inexpliquée selon la règle `securite-injection`.
- Si une requête ACP/HUB doit apparaître aussi comme tâche, créer/mettre à jour sa carte via MCP `create_task`/`update_task`, puis corréler Comms avec `binome.js --task-id <id> send`. `create_task` ne notifie pas l’agent; ne le remplace pas par `dispatch_task` pour une requête ACP.
- Les workers API directs NIM1/NIM2 du registre orchestrateur ne sont pas des sessions. Les providers ACP `nim`/`nim2` sont distincts et ne sont joinables que si une session ACP réelle est listée et acquitte le handshake.
- Ne jamais créer de conversation de remplacement, injecter dans une session non vérifiée, utiliser un toast ou le presse-papiers comme fallback, ni afficher/enregistrer un jeton CSRF ou une clé.
- Registre équipe : au démarrage de session, lire `memory_read key=team/roster projectId=<dossier-workspace>` (hphe-mcp) — le roster y est canonique, jamais dans un fichier. Si absent/périmé : chat-id → cascade Tango de CE workspace (`agy-hub list`+`read`) → bleubites ACP de CE workspace → vérifier par `reply` corrélée sur `comms.jsonl` → `memory_write team/roster`. Seuls Cash=devin et Tango=agy sont fixes ; bleubites dynamiques. `wake_devin` n injecte que dans le chat focalisé (misroute) ; bleubites via `sendToAcpAgent`/`wake_acp_agent` ; sessions vierges (msgs:0, sans titre) = coquilles muettes.
